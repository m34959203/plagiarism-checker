# 🔍 Антиплагиат — проверка текста на плагиат по интернету

CLI-инструмент (и веб-демо) на Python, который ищет в интернете дословные и
почти дословные заимствования фрагментов текста через поисковый API, считает
процент заимствований **по объёму символов** и выдаёт отчёт со ссылками на
источники.

**Живое демо:** https://antiplagiat.technokod.kz
**Исходники:** https://github.com/m34959203/plagiarism-checker

---

## Как это работает

1. **Ввод** — текст из `.txt`/`.md` файла или `--stdin`. Нормализуется
   (кавычки/тире → ASCII, схлопывание пробелов).
2. **Шинглы** — текст режется на предложения (с учётом сокращений вроде
   «и т. д.»), из каждого берётся 1–2 окна по 8–12 подряд идущих слов.
   Короткие предложения (< 6 слов) пропускаются как шум.
3. **Поиск** — каждая фраза ищется в поисковом API **в кавычках** (точная
   фраза). Берётся топ-5 результатов: заголовок, URL, сниппет.
4. **Сопоставление** — схожесть фразы и сниппета считается через
   `rapidfuzz.token_set_ratio`. Порог задаётся `--threshold` (по умолчанию 80).
   Опция `--fetch-source` дополнительно скачивает страницу и ищет фразу в
   полном тексте (по умолчанию выключено — экономия времени).
5. **Агрегация** — процент заимствований = (символы совпавших фрагментов) /
   (символы всех проверенных фрагментов) × 100. Это доля **объёма текста**, а
   не доля запросов. Источники группируются по домену.

### Как считается процент — важно

Каждый шингл — это фрагмент известной длины в символах. Процент считается так:

```
заимствовано, % = Σ длин совпавших фрагментов / Σ длин всех проверенных фрагментов × 100
```

Поэтому один длинный заимствованный абзац весит больше, чем одна короткая
случайно совпавшая фраза.

## Установка

```bash
git clone https://github.com/m34959203/plagiarism-checker.git
cd plagiarism-checker
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # и вписать ключ провайдера (см. ниже)
```

Требуется Python 3.10+. Зависимости: `requests`, `python-dotenv`,
`beautifulsoup4`, `rapidfuzz` — без тяжёлых ML-библиотек.

## Получение бесплатного ключа serper.dev (пошагово)

`serper.dev` — провайдер по умолчанию: даёт **2500 бесплатных запросов**
единоразово, без привязки карты.

1. Открой https://serper.dev
2. Нажми **Sign up** и войди через Google (или email).
3. После входа открой раздел **API Key** (в меню слева / в дашборде).
4. Скопируй ключ.
5. Вставь его в `.env`:
   ```
   SERPER_API_KEY=твой_ключ_сюда
   ```

Альтернативы (тоже бесплатные тарифы):

| Провайдер | Ключи в `.env` | Бесплатно | Где взять |
|-----------|----------------|-----------|-----------|
| `serper` (по умолч.) | `SERPER_API_KEY` | 2500 запросов | https://serper.dev |
| `google` | `GOOGLE_API_KEY`, `GOOGLE_CSE_ID` | 100/день | https://developers.google.com/custom-search |
| `brave` | `BRAVE_API_KEY` | ~2000/мес | https://api.search.brave.com |

### Пул ключей serper (несколько аккаунтов)

Можно задать несколько ключей serper — провайдер автоматически переключается на
следующий, когда текущий упирается в лимит (`429`), так что суммарный бесплатный
запас = `2500 × число ключей`:

```
# в .env — любой из вариантов, всё объединяется:
SERPER_API_KEYS=key_aaa, key_bbb, key_ccc
# или пронумеровать:
SERPER_API_KEY=key_aaa
SERPER_API_KEY_2=key_bbb
SERPER_API_KEY_3=key_ccc
```

`RateLimitError` (и досрочная остановка) наступает только когда исчерпаны **все**
ключи. Дубли отсекаются. ⚠️ Регистрация нескольких бесплатных аккаунтов ради
обхода лимита может противоречить правилам serper — используйте на свой риск;
для команды с несколькими легальными ключами это штатный режим.

## Использование (CLI)

```bash
# базовая проверка файла, HTML-отчёт в report.html
python -m plagiarism check input.txt --provider serper --threshold 80 \
    --max-queries 200 --report report.html

# из stdin
cat input.txt | python -m plagiarism check --stdin

# другой провайдер + подробный лог по каждому запросу
python -m plagiarism check input.txt --provider brave --verbose

# подтверждать совпадения загрузкой страниц-источников (медленнее, точнее)
python -m plagiarism check input.txt --fetch-source
```

Полный список флагов — `python -m plagiarism check --help`:

| Флаг | Назначение | По умолч. |
|------|------------|-----------|
| `input` / `--stdin` | входной файл или чтение из stdin | — |
| `--provider` | `serper` \| `google` \| `brave` \| `mock` | `serper` |
| `--threshold` | порог схожести 0..100 | `80` |
| `--max-queries` | потолок сетевых запросов за прогон | лимит провайдера |
| `--delay` | пауза между запросами, сек | `1.0` |
| `--fetch-source` | скачивать страницы для подтверждения | выкл. |
| `--cache` | файл дискового кэша | `.plagiarism_cache.json` |
| `--report FILE` | сохранить HTML-отчёт | — |
| `--min-words` / `--max-words` | размер окна-шингла | `8` / `12` |
| `--allow-short` | не требовать ≥ 10 000 символов | выкл. |
| `--verbose` | лог по каждому запросу | выкл. |

### Учёт лимита и докрутка за несколько запусков

- `--max-queries N` — жёсткий потолок числа запросов за один прогон.
- Все выполненные запросы кэшируются в `.plagiarism_cache.json`. **При повторном
  запуске уже проверенные фразы берутся из кэша и не тратят лимит.**
- При достижении лимита или ошибке `429` проверка **корректно останавливается**,
  сохраняет кэш и печатает, сколько фрагментов осталось. Достаточно запустить
  снова (например, на следующий день) — проверка продолжится с места остановки.

Пример: текст требует 500 запросов, а у Google лимит 100/день. Запускаете
5 дней подряд с `--provider google --max-queries 100` — и на пятый день
получаете полный отчёт, ничего не переплачивая.

## Веб-приложение

Тонкая обёртка над тем же движком (`webapp/app.py`, Flask). Проверка ставится в
**фоновую очередь** (`webapp/jobs.py`) и крутится в потоке через весь пул ключей;
страница опрашивает прогресс и по готовности показывает отчёт — так большой текст
(до 15 000 слов) проверяется целиком за один запуск, не упираясь в таймаут запроса.

```bash
pip install -r requirements-web.txt
WEB_PROVIDER=serper WEB_MAX_WORDS=15000 python webapp/app.py   # http://localhost:8790
# прод — ОДИН воркер с потоками (задачи хранятся в памяти процесса):
gunicorn --bind 0.0.0.0:8790 --workers 1 --threads 8 --timeout 120 webapp.app:app
# или через Docker:
docker compose up -d --build
```

Маршруты: `POST /check` → редирект на `/job/<id>` (страница прогресса);
`/job/<id>/status` (JSON), `/job/<id>/report` (готовый HTML-отчёт), `/health`.

## Ограничения метода

- Ловит прежде всего **дословные** и слегка изменённые заимствования.
  Глубокое перефразирование и перевод метод распознаёт **плохо** — для этого
  нужны семантические (эмбеддинговые) модели, которые здесь сознательно не
  используются ради лёгкости и бесплатности.
- Качество зависит от поискового индекса провайдера: закрытые базы, платные
  статьи и документы не в вебе найдены не будут.
- Процент — оценка по проверенным фрагментам-окнам, а не по каждому символу
  текста, поэтому это **индикатор**, а не юридически точная цифра.
